# Contributor onboarding

This walkthrough prepares a maintainer. Personal `/onboarding` is a separate, optional workflow that writes profile content and is unnecessary for repository checks.

1. Read [installation](INSTALLATION.md) and clone the personal fork if you intend to maintain it. Preserve the original MIT attribution and upstream links.
2. Read [architecture](ARCHITECTURE.md) and [components](COMPONENTS.md). Find the canonical skill or helper before editing a derived surface.
3. Run the [offline validation procedure](runbooks/validation.md). No service credentials, model downloads, or integrations are required.
4. Choose a focused change in an isolated checkout if others have active work. Use synthetic notes and repositories for tests.
5. Update documentation, regenerate derived packaging when needed, and let the delivery owner refresh indexes after reviewing staged paths.
6. Follow [contributing](../CONTRIBUTING.md), [development](DEVELOPMENT.md), and the PR template. Record exact checks and limits.

The [offline wiki](wiki/index.md) is the navigation entry point. It requires no remote wiki, account, publishing action, or sync process. User-owned integration setup belongs in the agent host and must not introduce shared secrets into Git.
